# M2.1 7-Bag Randomizer Spec

## Spec ID
`M2.1-7BAG-RANDOMIZER`

## Status
`Done`

## Scope
- Replace purely per-piece random selection with a 7-bag generator.
- Keep current gameplay flow intact (`current`, `next`, spawn timing).
- Provide deterministic seed support hook for future reproducibility work.

## Out of scope
- Replay system implementation.
- Score-rule changes.

## Design notes
- Bag contains all 7 tetromino types exactly once.
- After bag exhausts, shuffle and refill a new bag.
- Random source should be injectable later (seeded mode for M5).

## Implementation checklist
- [x] Add bag state to model layer (`Board` or dedicated generator helper).
- [x] Ensure each 7-piece window contains no duplicates and no omissions.
- [x] Integrate bag output into current/next piece pipeline.
- [x] Add minimal tests or debug assertions for bag invariants.
- [x] Document behavior in `doc/algorithms.md` once implemented.

## Acceptance criteria
- In any consecutive 7 generated pieces, all `TetrominoType` values appear once.
- `next` preview still updates correctly at every spawn.
- No gameplay freeze/regression caused by piece generation changes.

## Verification
- Manual: pending GUI smoke check (spawn/next flow) in local interactive session.
- Automated: `mvn test` includes `PieceBagTest` (bag uniqueness and current/next promotion checks).

## Rollback plan
- Keep old random generator behind a temporary switch during rollout.
- If regressions appear, switch back and isolate bag logic in a helper class.
