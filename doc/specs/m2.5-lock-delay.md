# M2.5 Lock Delay Baseline Spec

## Spec ID
`M2.5-LOCK-DELAY`

## Status
`Done`

## Scope
- Add lock delay when active piece first touches ground.
- Lock piece after delay if still grounded and no reset condition occurs.
- Keep hard drop behavior as immediate lock.

## Out of scope
- Advanced lock reset caps and level-scaling (future tuning).
- DAS/ARR timing policy.

## Design notes
- Use a fixed baseline delay for first rollout (tunable constant).
- Ground leave (piece moved/rotated off ground) cancels pending lock.
- Pause state must freeze lock-delay timer progression.

## Implementation checklist
- [x] Add grounded/lock-delay state fields in board model.
- [x] Start timer on first ground contact.
- [x] Finalize lock on timeout while still grounded.
- [x] Ensure hard drop bypasses delay and locks immediately.
- [x] Add visible state cue if needed (optional).

## Acceptance criteria
- Soft drop to ground does not lock instantly; delay window exists.
- Piece locks after delay if unchanged on ground.
- Hard drop still locks immediately.
- Pause/resume does not desynchronize lock timing.

## Verification

## Rollback plan
- Keep previous immediate-lock path behind runtime switch.
- If unstable, reduce scope to fixed delay without reset logic first.
