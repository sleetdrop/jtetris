# M3.1 DAS/ARR Input Timing Spec

## Spec ID
`M3.1-DAS-ARR-INPUT`

## Status
`Done`

## Scope
- Add deterministic horizontal movement repeat independent from OS keyboard repeat settings.
- Apply a baseline DAS (Delayed Auto Shift) and ARR (Auto Repeat Rate) policy.
- Keep existing rotate/hard drop/hold action semantics unchanged.

## Out of scope
- Soft drop timing tuning.
- Input buffering and IRS/IHS.
- Level-scaled DAS/ARR policy.

## Design notes
- Use a dedicated input repeater state machine with key press/release tracking.
- Choose latest pressed horizontal key when both left and right are held.
- Poll repeater via a lightweight Swing timer and emit signed horizontal steps.

## Implementation checklist
- [x] Add an input repeater component for horizontal DAS/ARR.
- [x] Switch left/right key handling to press/release bindings.
- [x] Poll held inputs via independent timer.
- [x] Reset held input state on pause/restart/focus-lost.
- [x] Add deterministic unit tests for repeater transitions.

## Acceptance criteria
- Holding left/right performs immediate first shift, then DAS pause, then ARR repeats.
- Behavior is stable even when OS keyboard repeat settings vary.
- Both-keys-held handling is deterministic and reproducible.
- Pause/restart/focus transitions do not leave stuck horizontal movement.

## Verification
- Manual: hold left/right and compare perceived DAS/ARR cadence.
- Automated: `InputRepeaterTest` covers immediate shift, DAS threshold, ARR repeat, both-key priority, reset.

## Rollback plan
- Revert `TetrisFrame` key handling back to one-shot left/right actions.
- Keep `InputRepeater` unused until next attempt.
