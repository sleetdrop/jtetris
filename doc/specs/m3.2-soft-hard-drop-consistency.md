# M3.2 Soft/Hard Drop Consistency Spec

## Spec ID
`M3.2-SOFT-HARD-DROP-CONSISTENCY`

## Status
`Done`

## Scope
- Make soft drop cadence deterministic and independent from OS key-repeat settings.
- Keep hard drop behavior immediate and stable while soft drop is held.
- Reuse the existing input poll loop introduced in M3.1.

## Out of scope
- Soft drop score bonuses.
- Gravity/soft-drop speed scaling by level.
- Lock-delay tuning changes.

## Design notes
- Add a dedicated soft-drop repeater with immediate first step + fixed repeat interval.
- Bind Down key as press/release, not one-shot key action.
- Clear held soft-drop state on pause/restart/focus-lost to avoid sticky movement.

## Implementation checklist
- [x] Add a `SoftDropRepeater` component with deterministic timing.
- [x] Add unit tests for repeater behavior.
- [x] Switch `↓` handling in `TetrisFrame` to press/release + poll integration.
- [x] Ensure hard drop remains immediate while soft-drop logic coexists safely.
- [x] Update docs to reflect input timing semantics.

## Acceptance criteria
- Holding `↓` gives a repeatable soft-drop cadence across systems.
- Pressing `Space` still hard-drops and locks immediately.
- Releasing `↓` stops soft-drop repeats immediately.
- Pause/restart/focus-loss clears held soft-drop state.

## Verification
- Manual: verify hold/release `↓` cadence and hard drop interaction in GUI.
- Automated: `SoftDropRepeaterTest` covers immediate step, repeat cadence, release, reset.

## Rollback plan
- Revert `↓` key binding to one-shot action in `TetrisFrame`.
- Keep `SoftDropRepeater` unused until next iteration.
