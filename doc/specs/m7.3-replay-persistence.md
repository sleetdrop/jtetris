# M7.3 Replay Persistence

## Spec ID
- `M7.3-REPLAY-PERSISTENCE`

## Status
- `Done`

## Scope
- Goal:
  - Add export/import persistence for seeded replay streams so a finished run can be saved and deterministically replayed later.
- File allowlist (exact paths):
  - `doc/specs/m7.3-replay-persistence.md`
  - `src/main/java/net/vetcafe/jtetris/model/ReplayPersistence.java`
  - `src/test/java/net/vetcafe/jtetris/model/ReplayPersistenceTest.java`
  - `doc/algorithms.md`
  - `doc/overview.md`
  - `doc/specs/context-pack.md`

## Out of scope
- Wiring replay export/import to menus or key bindings.
- Binary/compressed replay formats.
- Changes to gameplay mechanics, score logic, or RNG behavior.

## Design notes
- Use a simple text format (`v1`) to keep files diff-friendly and easy to inspect.
- Persist only deterministic payload (`seed` + ordered `ReplayAction` names).
- Parse defensively and fail fast on malformed input.

## Implementation checklist
- [x] Step 1: Add model-layer replay persistence utility (`save`/`load`) with a stable text format.
- [x] Step 2: Add a replay round-trip test that reconstructs board state from imported replay payload.
- [x] Step 3: Document replay file format and intended future UI integration points.

## Acceptance criteria
- Replay data can be saved and loaded without losing action order.
- Loaded replay payload can drive `Board.replayFromSeed(...)` deterministically.
- Malformed replay files fail with clear exceptions (no silent corruption).
