# M3.3 Input State Transitions Spec

## Spec ID
`M3.3-INPUT-STATE-TRANSITIONS`

## Status
`Done`

## Scope
- Prevent gameplay input from leaking into modal UI states (score dialogs, leaderboard, new-game prompt).
- Unify gameplay input eligibility checks across key handlers and repeat polling.
- Ensure held input states are cleared on modal enter/exit, pause, restart, and focus transitions.

## Out of scope
- Implementing advanced input buffers (IRS/IHS).
- Input remapping or custom key profiles.
- Replay/recorded input pipelines.

## Design notes
- Introduce a modal guard flag in `TetrisFrame` and gate gameplay actions behind one helper.
- Wrap `JOptionPane` calls with a `withModalInputBlocked(...)` helper using `try/finally`.
- Clear repeaters before and after modal operations to avoid sticky movement.

## Implementation checklist
- [x] Add modal input guard state in `TetrisFrame`.
- [x] Replace direct dialog calls with guarded wrappers.
- [x] Route action and poll eligibility through one method (`isGameplayInputEnabled`).
- [x] Keep focus restoration behavior compatible with modal windows.
- [x] Update roadmap/docs/context notes.

## Acceptance criteria
- While dialogs are open, gameplay controls do not move or mutate board state.
- Closing dialogs does not leave held movement/soft-drop state active.
- Pause/restart/focus-loss behavior remains stable.

## Verification
- Manual: open leaderboard/score dialogs while holding movement keys and verify no post-dialog drift.
- Automated: project regression suite passes (`mvn clean test`).

## Rollback plan
- Revert `TetrisFrame` modal wrappers to direct `JOptionPane` calls.
- Remove `modalActive` gating and keep existing pause/game-over guards.
