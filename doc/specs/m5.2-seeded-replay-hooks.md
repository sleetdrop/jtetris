# M5.2 Seeded Replay Hooks Spec

## Spec ID
`M5.2-SEEDED-REPLAY-HOOKS`

## Status
`Done`

## Scope
- Add deterministic replay hooks at model level for debugging and regression triage.
- Expose seed metadata for seeded boards.
- Record and re-apply discrete gameplay actions using a stable action enum.

## Out of scope
- Persisting replay files to disk.
- UI replay controls.
- Frame-perfect timestamp playback.

## Design notes
- Replay determinism is driven by `Board(seed)` + ordered `ReplayAction` stream.
- `Board.applyReplayAction(...)` centralizes action execution and recording.
- `Board.replayFromSeed(...)` rebuilds state from seed + action stream.

## Implementation checklist
- [x] Add `ReplayAction` enum in model package.
- [x] Add action recording list and seed getter in `Board`.
- [x] Add replay-application API and replay reconstruction helper.
- [x] Add deterministic tests validating state equivalence after replay.
- [x] Update roadmap/docs/context.

## Acceptance criteria
- Same seed + same action stream yields same board state.
- Reset clears recorded action stream for a new run.
- Seed visibility is available for seeded boards and absent for unseeded boards.

## Verification
- Manual: N/A (model-level replay hooks).
- Automated: `ReplayHooksTest` + full `mvn clean test`.

## Rollback plan
- Remove replay-specific APIs from `Board` while keeping existing gameplay APIs.
- Keep tests gated to model behavior unrelated to replay hooks.
