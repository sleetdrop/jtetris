# M7.1 Runtime Theme Switching

## Spec ID
- `M7.1-RUNTIME-THEME-SWITCHING`

## Status
- `Done`

## Scope
- Goal:
  - Allow switching between `auto|light|dark` at runtime from UI without restarting the app.
- File allowlist (exact paths):
  - `doc/specs/m7.1-runtime-theme-switching.md`
  - `src/main/java/net/vetcafe/jtetris/ui/TetrisFrame.java`
  - `src/main/java/net/vetcafe/jtetris/ui/GamePanel.java`
  - `src/main/java/net/vetcafe/jtetris/ui/SidePanel.java`
  - `src/main/java/net/vetcafe/jtetris/ui/UiTheme.java`
  - `doc/overview.md`
  - `doc/specs/context-pack.md`

## Out of scope
- Persisting theme preference to disk.
- Reworking tetromino palette design values.
- Changes to gameplay mechanics or timing.

## Design notes
- Keep `UiTheme.modeOverride()` startup contract intact for `-Djtetris.theme=auto|light|dark`.
- Add a runtime override setter/getter in UI layer and trigger repaint/revalidate on all game surfaces.
- Ensure modal dialogs opened after switching adopt the updated theme values.

## Implementation checklist
- [x] Step 1: Add runtime theme mode state and setters with safe fallback behavior.
- [x] Step 2: Add menu actions for `Auto/Light/Dark` and wire full-window refresh.
- [x] Step 3: Verify keyboard focus/input repeaters are unchanged after switching.

## Acceptance criteria
- User can switch theme mode in running app and see immediate UI updates.
- Existing launch option (`-Djtetris.theme=...`) still works.
- No gameplay/input regression when switching during active play.
