## Scope

## Out of scope
- Migrating specific business flows (game-over, leaderboard, exit).
- Changing score persistence behavior.

## Design notes
- Add overlay state model with explicit visibility and focus ownership.
- Overlay activation blocks gameplay input and clears held repeater state.
- Overlay rendering remains inside game stage boundaries for handheld-style UX.
- Visual style is board-top HUD windows (no full-screen dim mask).
- While overlay is active, board rendering continues but gameplay logic is paused.
- Overlay foundation must support keyboard-first interaction.
- Default overlay key contract: `Enter` and `Space` confirm, `Esc` cancels/dismisses.
- Overlay sizing uses mixed strategy: content-adaptive layout with bounded minimum/maximum size.
- Overlay transitions use short fade + subtle slide motion (handheld HUD feel) with conservative timing.

## Implementation checklist
- [x] Introduce overlay container/component and lifecycle APIs.
- [x] Wire input blocking (`modalActive` evolution) to overlay visibility.
- [x] Add a simple non-critical demo overlay (info panel) to validate framework.

## Acceptance criteria
- Overlay appears inside stage and does not spawn OS-level dialogs.
- Overlay uses HUD-style panel rendering without global darkened backdrop.
- Movement/rotation/drop inputs are blocked while overlay is active.
- Gravity/gameplay progression is paused while overlay is visible.
- `Enter`/`Space`/`Esc` actions are consistent across overlays.
- Overlay size stays readable via min/max bounds while adapting to panel content.
- Overlay enter/exit animation remains short and non-disruptive to input recovery.
- Closing overlay restores gameplay control without stuck input states.
