## Out of scope
- Java source, tests, `pom.xml`, package moves, dependency changes, and gameplay behavior.
- Full conversion of all historical `doc/specs/m*.md` files into OpenSpec capabilities.
- Adding an OpenSpec CLI dependency or enforcing a specific package manager.
- Changing score storage, replay format, UI theme behavior, or keyboard semantics.

## Design notes
- Treat `doc/specs` as historical project memory after this migration. New non-trivial work should start in `openspec/changes/<change-id>/`.
- Keep the strict scope discipline that already works for this repo: active change, file allowlist, explicit out-of-scope items, small commits, and `mvn clean test` before completion.
- Make `AGENTS.md` the agent-neutral root entry point, with Codex-specific preference expressed as practical workflow guidance rather than GitHub Copilot prompts.
- Keep GitHub repository integration optional. GitHub PR templates may remain as wrappers, but Copilot prompt files and GitHub issue templates should not define the primary workflow.

## Acceptance criteria
- `AGENTS.md` points new work to OpenSpec and remains usable by Codex and other agents.
- `openspec/project.md` and `openspec/AGENTS.md` describe the project, constraints, validation commands, and agent routine.
- `openspec/specs/project-workflow/spec.md` captures the repo workflow requirements in OpenSpec style.
- README and CONTRIBUTING no longer direct contributors to Copilot prompts as the primary workflow.
- Copilot-specific prompt files are removed or no longer presented as required project workflow.
- `mvn clean test` passes.
